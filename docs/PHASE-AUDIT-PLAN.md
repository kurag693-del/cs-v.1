## Приоритеты (что делать дальше)

### P0 — до уверенного продакшена в РФ

1. **Контур публикации:** подтвердить сценарии **Telegram** end-to-end в вашей среде; для **VK** — либо довести OAuth/токены и прогнать приёмку, либо явно зафиксировать в продукте «только Telegram» до появления VK.
2. **Коммерция в РФ:** когда решите продавать подписку — фаза **7** (ЮKassa или иной РФ-эквайринг, **152-ФЗ**, политики, экспорт данных). Stripe как есть может оставаться для не-РФ или быть заменён — решение продуктовое.
3. **RBAC публикации:** ручная проверка `EDITOR` + выключенный `editorsCanPublish` vs **ADMIN** (код уже есть — см. `publish-guard.ts`).

### P1 — качество и уверенность перед масштабированием

**Статус (выполнено в репозитории):**

4. **Сквозной сценарий:** Vitest фиксирует правила **одобрения + переход в SCHEDULED** (`draft-to-scheduled-gates.test.ts`) и **гейт публикации по ролям** (`publish-guard.test.ts` с моком Prisma). **Playwright:** `e2e/smoke.spec.ts` (главная, редирект `/dashboard` → `/login`), скрипт `npm run test:e2e`, шаг в `.github/workflows/ci.yml` после smoke. Полный браузерный сценарий с логином и реальной генерацией — по-прежнему бэклог (нужны фикстуры/тестовый пользователь).
5. **Тесты прав workspace:** закрыто через `publish-guard.test.ts` (VIEWER, EDITOR + `editorsCanPublish`, ADMIN, legacy-бренд).
6. **Зависимости:** удалены неиспользуемые **`ts-node`**, **`oslo`**; добавлен **`.npmrc`** (`legacy-peer-deps=true`) для стабильного `npm ci` при Prisma 6 и `@lucia-auth/adapter-prisma`.
7. **Документация:** обновлён **`ROADMAP.md`** (OpenRouter, фазы 2/8/10, бэклог моделей, приёмка фаз).
