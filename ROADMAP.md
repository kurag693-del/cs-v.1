## Фаза 1. Ядро ИИ + фикс генерации

### 🎯 Цель и влияние на конкурентные преимущества
- Вынести генерацию в мульти-провайдерную архитектуру (GigaChat/YandexGPT/VK AI), чтобы убрать lock-in и дать пользователю выбор по цене/качеству.
- Повысить качество контента через строгий `buildPrompt`, структурную валидацию (Хук → Тело → CTA) и фильтрацию шаблонов.
- Сделать прозрачность генераций выше: фиксировать выбранный провайдер в `Generation.metadata` для аналитики затрат и качества.

### 📁 Затронутые файлы (точные пути)
- **Рефакторинг:** `src/lib/generate/actions.ts` (вынос логики провайдера, фикс `buildPrompt`, валидация структуры/длины, запись provider в metadata).
- **Рефакторинг:** `src/lib/ai/types.ts` (типизация `AIProvider`, `ProviderId`, контракт результата генерации/стрима).
- **Создание:** `src/lib/ai/providers/types.ts` (единый интерфейс `generate`, `stream`, `estimateTokens`).

- **Рефакторинг:** `src/components/features/TextGeneratorForm.tsx` (выбор провайдера пользователем).
- **Рефакторинг:** `src/components/features/TextGenerator.tsx` (проброс `provider` в server action).

### ⚙️ Технические требования
- TypeScript strict: без `any`, с явными интерфейсами `AIProvider`, `GenerateParams`, `StreamChunk`.
- Валидация на границах: Zod для входа (`provider` whitelist), Zod для результата генерации (`hook/body/cta/hashtags`).
- `buildPrompt` должен делать безопасную и полную замену всех `{{variable}}`; при пропуске обязательного плейсхолдера — ошибка валидации.
- Жесткие правила качества: `body >= 300`, итоговая структура обязательна, запрет шаблонных фраз централизованным списком.
- Ошибки через единый формат `{ success, data?, error }`; без утечки секретов и внутренних stack trace в клиент.
- Без внешних Supabase/Google AI вызовов: убрать `@google/generative-ai` из потока выполнения, оставить только провайдерный слой.
- Интеграция с Lucia Auth: операции генерации только для валидного `userId`, полученного из сессии/заголовка.

### ⚙️ Технические требования
- Telegram: `sendMessage`/`sendPhoto`, обязательное экранирование MarkdownV2.
- VK: `photos.getWallUploadServer` + `wall.post`; обработка токена и срока жизни.
- Дзен: официальный Publisher API; если недоступен — fallback сценарий (RSS/headless) как деградация, а не блокер.
- Upstash Redis Queue: экспоненциальный retry с jitter, max attempts, DLQ с причиной последнего падения.
- Идемпотентность: `idempotencyKey` в `Post.metadata`/выделенном поле, проверка перед отправкой.
- Безопасность: секреты платформ только в env, не логировать access tokens, добавить rate-limit на публичные route handlers.
- Совместимость с Lucia: публикация выполняется в контексте владельца поста, без подмены `userId` из тела запроса.
